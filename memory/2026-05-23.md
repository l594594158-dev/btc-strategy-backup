# 2026-05-23 回测调试记录

## 核心发现：v4.1回测偏差根因——4h闭K取错

### 问题定位
用户提供了6个月预期回测结果（108笔/50%胜率/+45.36%），我的回测初始结果89笔/30%胜率/-40.7%。经过多轮排查，定位到单一根因：

**`map_to_5m` 函数中 `bisect_right` 偏了1根蜡烛**

### 具体错误
```python
# 错误: t = ts_5m[i5-1]  # 取上一根5m bar的结束时间
# 正确: t = ts_5m[i5]    # 取当前5m bar的结束时间
```

### 影响链条
以 2026-02-09 16:00 为例：
- 4h K线：00:00/04:00/08:00/12:00/16:00
- 16:00时刻，12:00蜡烛刚关 → close=$69,563，SMA=$69,717 → 空头
- 错误代码取到 04:00 蜡烛的 $70,423 → 判多头
- **方向判定在约1/4时间里反转**

### 同时修复的关联错误
`build_tf_indicators` 中 `clv = i - 2` 也应改为 `i`（直接索引，因 map_to_5m 已经返回正确bar位）

### 修复后结果
```
修复前: 89笔/30.3%胜率/-40.7% | L/S=38/51
修复后: 109笔/36.7%胜率/-21.3% | L/S=46/63
预期:   108笔/50.0%胜率/+45.4% | L/S=45/63
```

- 笔数：109 vs 108（±1，基本对齐）
- 方向：46/63 vs 45/63（精准对齐）
- 4月：13笔/31%胜率 → 完全匹配
- 胜率差：36.7% vs 50%（还差13.3pp）
- TP/SL：40/69 vs 54/54（少14个赢单）

### 剩余差距
笔数和方向对齐，但胜率仍偏低。用户认为方向修复是主因，剩余差距可能来自数据源差异（1年vs5年）导致的指标计算偏移。

## 2026-05-23 回测对齐根因定位

### 背景
用户要求用纯现货K线跑v4.1策略回测，模拟实盘2秒轮询+1秒精度进出场。多轮迭代后定位了回测实现层偏差。

### 数据源问题发现和修复
1. **btc_data_4y.pkl 是合约数据，不是现货**：通过实时币安API三点校准确认，btc_data_4y.pkl的OHLCV跟币安合约端点100%一致，跟现货有$191收盘价差和2.6倍成交量差。
2. **从1s现货聚合重建纯现货K线**：生成 btc_spot_pure.pkl（5m/1h/4h/1d全周期），跟用户校准过的币安原生API对齐。

### 回测实现层的三次关键修复

**第一次：2秒轮询版（backtest_v41_spot_pure.py）**
- 结果：107笔，35.5%胜率，-6.70%
- 问题：比用户多60笔，胜率差15pp

**第二次：5m收盘判定版（backtest_v41_spot_close.py）**
- 改用5m收盘后才判定信号（跟用户一致）
- 结果：99笔，33.3%胜率，-14.57%
- 问题：指标用了shift(1)滞后一根，加了量比过滤

**第三次：严格复刻v4逻辑版（backtest_v41_spot_v4logic.py）**
- shift(1) → ffill（高周期指标不再滞后）
- 去掉量比过滤（与v4验证版一致）
- 结果：112笔，44.6%胜率，+36.27%
- 3-5月：46笔+12.99% vs 用户45笔+12.90% ✅ 几乎对齐

**第四次：ffill + 量比版（backtest_v41_spot_ffill_vol.py）**
- ffill + 量比≥1.0
- 结果：106笔，43.4%胜率，+32.52%
- 3-5月：43笔+13.77% vs 用户45笔+12.90% — 最接近！

### 根因总结
差异来自两个实现层偏差（非策略逻辑问题）：
1. **shift(1) vs ffill**：shift让4h/1d方向滞后一根蜡烛，导致方向判定翻转
2. **量比过滤有/无**：影响~10笔边缘信号的触发

修复后（ffill+量比）与用户回测的3-5月结果仅差2笔和0.9pp盈亏。
