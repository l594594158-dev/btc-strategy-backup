## 三、运行逻辑（主循环，每5秒）

```
1. 获取4周期K线（5m/1h/4h/1d），各limit=200根
2. calc()计算所有指标：ATR/MACD/RSI/布林/ADX/成交量
3. 数据不足14根 → 跳过本轮
4. load_state()加载state（幽灵仓位标签修复+写入验证）
5. 检查交易所与state一致性（幽灵仓位防护+交易所→state同步）
6. 打印状态UI（价格/持仓/SL/TP/信号）
7. 有持仓时：每30分钟发送手动参考通知
8. 有持仓时：检查移动止盈（激活1%/触发0.6%）
9. 有持仓时：每60秒检查SL/TP完整性
10. 检查开仓信号 → 300秒冷却 → 1.5%间隔验证
11. 开仓 → 市价成交 → 挂SL/TP → 更新state → 写notify_queue
12. 异常捕获 → work_log记录 → 等待5秒继续
```

## 六、仓位同步机制（v2.13）

```
启动时：
  - 读取state.json
  - 验证交易所实际持仓与state一致性
  - 交易所无仓但state有仓 → 清空state（幽灵仓位防护）

load_state()时：
  - 旧格式reason='幽灵仓位同步' → 'bot_recovered'
  - positions数组中遗留幽灵标签 → 同步更新为bot_recovered

save_state()时（v2.13新增）：
  - 写入后验证positions数量匹配
  - 验证失败重新写入并记录日志

主循环中：
  - 每次循环检查交易所实际持仓
  - 交易所无仓但state有仓 → 清空state
  - 交易所有仓但state无 → 同步到state（v2.13新增）

健康检查（每5分钟，v2.13新增）：
  - 交易所有仓但state无 → 自动从交易所恢复仓位到state
  - state有仓但交易所无 → 清空state
```

## 七、微信通知机制

```
开仓/补仓：
  auto_trade.py → 写入notify_queue.json(sent=false) → notify_alert()

平仓/移动止盈：
  auto_trade.py → 直接调用send_wechat_msg() → 同时写notify_queue

手动参考信号：
  每30分钟检测一次，write last_alert.json

send_notify.py（cron每分钟执行）：
  读取notify_queue.json → 调用openclaw message send → 更新sent=true
```

## 八、1.5%间隔验证逻辑

```
开仓前：
  1. 获取交易所所有实际持仓
  2. 有持仓时：逐个检查间隔
     - 做多：新仓价必须 < 现有仓价 × 0.985
     - 做空：新仓价必须 > 现有仓价 × 1.015
  3. 任一仓间隔不足1.5% → 直接return，拒绝开仓
  4. 间隔验证通过 → 市价开仓

补仓合并：
  - 撤销旧SL/TP
  - 计算所有仓加权均价
  - 以新均价统一挂SL/TP
  - state合并为单仓位
  - 发送微信通知
```
