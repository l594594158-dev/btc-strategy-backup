# 修复文档 v2.17

## v2.17 (2026-05-18): 补仓ADX安全保护

### 背景
原策略中，补仓仅检查价格间隔（2.5%），未考虑趋势强度变化。若趋势在开仓后增强，补仓风险同步放大。

### 修复内容
1. **首仓记录ADX**：开首仓时在state.json中记录当时的`first_entry_adx_1h`和`first_entry_adx_4h`
2. **补仓ADX校验**：触发补仓时，比较当前1h和4h ADX与首仓对应值
   - 当前ADX ≤ 首仓ADX（两个周期都满足）→ 允许补仓
   - 任一周期当前ADX > 首仓ADX → 拒绝补仓（趋势增强=不宜加仓）
3. **合并仓位保留ADX**：补仓后合并仓位时，保留首仓原始ADX值，支持后续二次补仓校验
4. **向后兼容**：v2.16及之前的旧仓位无ADX记录，自动跳过检查

### 影响范围
- `open_position()` 新增 `adx_1h`、`adx_4h` 参数
- `state.json` positions 新增 `first_entry_adx_1h`、`first_entry_adx_4h` 字段
- 主循环调用 `open_position` 时传入 `data['1h']['adx']` 和 `data['4h']['adx']`

### 修复

```python
    k4h = binance.fetch_ohlcv(SYMBOL, timeframe='4h', limit=200)
    k1d = binance.fetch_ohlcv(SYMBOL, timeframe='1d', limit=200)
    return k5m, k1h, k4h, k1d

def calc(df):
    if len(df) < 14:
```

## 修复三：开仓间隔1.5%验证

### 规则
所有仓位之间必须保持1.5%间隔（不分方向）：

| 新仓方向 | 间隔要求 |
|---------|---------|
| 做多 | 新仓价 < 现有仓价 × 0.985 |
| 做空 | 新仓价 > 现有仓价 × 1.015 |

### 修复
开仓前验证所有现有持仓，不合格直接拒绝（不先下单再回撤）：

```python
# v2.12: 所有仓位之间必须保持1.5%间隔（不分方向）
exchange_pos = [p for p in binance.fetch_positions()
                if p.get('symbol') == SYMBOL and float(p.get('contracts', 0)) > 0]

if exchange_pos:
    for ep in exchange_pos:
        existing_entry = float(ep['entryPrice'])
        if direction == 'long':
            gap_pct = (existing_entry - candidate_price) / existing_entry * 100
        else:
            gap_pct = (candidate_price - existing_entry) / existing_entry * 100
        
        if gap_pct < 1.5:
            log(f"⛔ 开仓间隔不足({gap_pct:.2f}% < 1.5%)")
            return None
```

## 修复四：微信通知发送失败（cron环境下node路径问题）

### 问题
早上开仓没有收到微信通知，send_notify.log 显示：
```
/root/.local/share/pnpm/openclaw: 20: exec: node: not found
```

## 修复八：开仓后state被旧变量覆盖 (v2.12.6)

### 问题
open_position() 内部保存了正确的 state（含新仓位），但主循环紧接着用开仓前加载的旧 state 变量又 save_state() 一次，导致新仓位被覆盖为无仓状态。

日志表现：
```
[22:32:07] 💾 state已写入: in_position=True positions=1仓  ← open_position 正确保存
[22:32:07] 💾 state已写入: in_position=False positions=0仓 ← 主循环覆盖！
```

### 影响
- 开仓后脚本以为没仓位 → 移动止盈不触发 → SL/TP 检查跳过
- 后续只能靠"交易所无仓但state有仓"的异常检测机制清空恢复

### 修复
开仓后 reload state 再更新 last_signal_time：

```python
open_position(sig, price, atr, reason, QTY)
state = load_state()  # 重新加载，获取 open_position 已保存的正确 state
state.setdefault('last_signal_time', {})[sig] = time.time()
save_state(state)
```
